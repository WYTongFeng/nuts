# 本地第三版：自动多模型润色与复核验证

日期：2026-10-23。

## 验证对象

中文界面选择多个本地润色模型 → 依次调用 Ollama → 保存候选 → 指定模型统一复核 → 展示结果和耗时 → 导出实验记录。

## 实现

- 多模型模式最多三个不同模型，每个独立根据原文生成一个候选；重复的模型选择合并。
- 保留单模型一个候选、单模型三种策略。所有模式均可指定统一复核模型。
- 先完成生成，再复核通过机械内容检查的候选；失败、停止或未完成复核的候选不自动推荐。
- 同模型连续请求保温五分钟；切换和整轮结束主动释放。停止按钮在当前请求结束后生效。
- RTX 3060 配置按保守文本预算选择 4K / 8K，上限 8K，超预算明确拒绝；不是模型精确分词器。
- 按文章长度设置输出预算，拒绝截断输出；支持的模型请求关闭思考。
- 润色前将已加载 GPT-2 从 CUDA 移回 CPU；检测时再移回既有设备。
- 候选记录生成模型、复核模型、请求耗时、上下文、输出预算、思考设置和可用的加载耗时。加载耗时缺失记为 null，不写成零。

## 自动化验证

执行 `.venv/bin/python -m unittest discover -s tests -v`：55 项通过。

新增覆盖：

- 不同生成/复核模型的 HTTP 请求与结果、先卸载旧模型再调用新模型、结束后释放。
- 同一模型连续请求保持加载。
- 空/超长复核输出、无效配置、远程或不存在模型的拒绝。
- 复核超时、格式失败不产生 eligible 候选；内容检查失败不调用复核模型。
- 4K / 8K 预算选择以及超预算拒绝。
- 拒绝复核模型返回额外字段覆盖服务端计算的通过状态。

保留检测、保留检查、请求校验、同源检查、忙碌冲突及 GPT-2 的原有测试。

另执行 Python 编译检查、`node --check app.js`、`git diff --check`。

## 浏览器与服务交互验证

使用隔离的本地模拟 Ollama HTTP 服务，真实运行 Nuts 服务及浏览器界面：

1. 默认选中 Qwen3 4B、Gemma3 4B，复核模型为 Qwen2.5 7B。
2. 点击示例与开始，出现两个不同模型的候选。
3. 两份候选显示指定复核模型与生成/复核耗时，成功结果可切换查看。
4. 请求日志显示生成模型切换前卸载，复核模型连续处理两次后才卸载。
5. 另一轮在首个请求中点击停止：只保留首个候选，默认原文，明确提示未复核版本不自动推荐。
6. 界面截图保存在本机忽略目录 `output/preview-v3.png`，不作为真实模型效果证明。

## 验证范围限制

- 当前机器没有目标 Lenovo RTX 3060，未测 Windows GPU 实际吞吐或加速倍数。
- Ollama 生成和复核流程以模拟服务验证，没有下载和实跑这九款真实模型。模拟输出和约两秒的人工延迟不是模型质量或速度数据。
- GPT-2 测试使用真实本地依赖；CUDA 内存迁移路径没有在 NVIDIA 硬件实测。
- 没有测 Turnitin、GPTZero、ZeroGPT 或 QuillBot；不声称达到全平台 0。
- 自动推荐仍依据内容检查、模型复核和本地规则参考，不能证明原意完全保留或预测外部成绩。
